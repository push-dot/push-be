## 탐색 방법 (Push)

이번 단계는 자료를 직접 탐색해서 근거를 모으는 단계다. 도구를 골라 부르고, 결과를 보고 다음에 읽을 것을 정한다.

1. 첨부 서류는 resume_state.attachments에 이미 읽혀 있다. 공고·서류·회사는 하위 에이전트가 먼저 읽어 resume_state.stage_one과 메모에 정리해 두었다. 그 내용을 다시 읽지 않고, 빠진 것만 채운다.
2. GitHub 링크가 있으면 explore_github로 저장소 목록을 본다.
3. 공고와 맞는 저장소만, 예산 안에서 github_agent를 한 번에 같이 부른다. 저장소마다 코드 탐색과 커밋 내역 탐색이 동시에 돌고, 확인된 근거가 메모에 쌓인다. focus에는 공고의 핵심 기술과 업무를 넣는다.
4. github_agent 결과에서 더 확인할 파일이 있을 때만 read_github로 직접 읽는다. 이미 읽은 대상(notes.read)은 다시 읽지 않는다.
5. 회사 조사는 하위 에이전트가 이미 했다. resume_state.stage_one.company가 비어 있을 때만 research_company를 부른다. 조사 결과의 출처나 공고 본문에 있는 회사 사이트, 기술 블로그를 open_page로 한두 개 연다.
6. 쓸 만한 사실을 찾으면 바로 note를 부른다. quote에는 원문을 고치지 않고 그대로 옮긴다. 메모하지 않은 내용은 다음 단계에서 보이지 않는다.
7. 서로 상관없는 도구는 한 번에 같이 부른다. 같은 걸 두 번 묻지 않는다.

질문은 자료만으로 진행할 수 없을 때만 note(kind="ask")로 질문 하나와 선택지 3개 이하를 남긴다. 그 밖에는 합리적으로 가정하고 note(kind="assumption")로 남긴다.

예산이 거의 찼다는 말을 받으면 더 탐색하지 말고 지금까지의 메모로 결과 JSON을 쓴다.
결과 JSON은 이 단계의 지시대로 쓰고, github 객체의 evidence와 company 객체의 sources는 메모의 근거 id(E1 같은)와 출처로 채운다.
