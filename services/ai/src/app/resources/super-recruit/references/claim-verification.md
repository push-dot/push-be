# 서류 주장 확인 기준

목적: 서류에 적힌 역량이 사실인지 **면접에서 확인할 부분**을 찾는다. 사실이 아니라고 단정하지 않는다.

## 1. 판단 수준
| 수준 | 화면 | 쓰는 때 |
|---|---|---|
| `CHECK` | 확인 필요 | 아래 신호가 하나 이상 있고, 서류 안에서 해소되지 않을 때 |
| `SUPPORTED` | 근거 충분 | 기간·규모·역할·방법이 서로 맞고 구체적일 때 |
| `UNKNOWN` | 판단 보류 | 서류에 판단할 정보가 없을 때 |

## 2. 신호 (하나씩 점검한다)
1. **수치만 있고 방법이 없다**: 성과 수치는 있는데 무엇을 직접 바꿨는지(코드·설정·구조) 설명이 없다.
2. **주어가 흐리다**: "팀이 달성", "참여하여"와 "직접 설계"가 섞여 본인 기여 범위가 안 보인다.
3. **기간·규모가 안 맞는다**: 재직 기간보다 프로젝트 기간이 길다, 같은 기간에 주요 역할이 여러 개 겹친다, 트래픽·인원 규모가 회사 규모와 동떨어진다.
4. **기술 나열과 사용 맥락이 따로 논다**: 기술 스택 목록에는 있는데 경력 본문에서 쓴 흔적이 없다.
5. **문장 구조는 고급인데 빈칸이 비었다**: "대용량 트래픽 처리 파이프라인 고도화" 같은 문장에 처리량·장애 사례·선택 근거가 없다.
6. **연차 대비 깊이**: 기준선이 있을 때만 쓴다. "같은 연차 서류보다 기술 설명이 짧아요"처럼 통계로 말한다.
7. **결과를 확인 행위로만 말한다**: "~을 검증함", "~을 확인함"으로 끝나고 결과 상태가 없다.

## 3. 인용 규칙
- 인용은 **지원자가 낸 서류**에서만, 짧게(한 구절) 한다.
- 참고 데이터는 숫자와 경향으로만 말한다. 템플릿 문장이나 다른 사람의 표현은 절대 쓰지 않는다.
- 기준선을 쓰지 못한 구간이면 6번 신호를 쓰지 않고, 기준선이 없다는 사실도 화면에 따로 말하지 않는다.

## 4. 하지 않는 것
- 합격·불합격·추천·비추천·탈락·부적합 판단, 점수로 줄 세우기.
- 서류 밖 정보(나이, 출신, 성별 추정 등)로 판단하기.
- "거짓말", "허위", "조작" 같은 단정. 대신 "면접에서 직접 확인해 보는 게 좋아요".

## 5. 카드 문장 모양
- 제목: 확인할 대상 한 구절 ("p99 420ms → 180ms의 본인 역할")
- 이유: 신호 + 서류 근거 한 문장 ("성과 수치는 구체적인데, 무엇을 직접 바꿨는지 설명이 같은 연차 서류보다 짧아요.")
