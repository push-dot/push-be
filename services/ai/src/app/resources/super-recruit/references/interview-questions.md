# 검증 면접 질문 기준

목적: 서류에 적힌 역량이 본인의 것인지, 실제로 해 봤는지를 담당자가 직접 확인하게 돕는다.

## 1. 질문 순서
1. 서류 검토에서 "확인 필요"였던 항목부터, 항목당 1–2개.
2. 공고의 필수 요건 중 서류 근거가 약한 것.
3. 남은 자리는 핵심 요건 검증 질문으로 채운다. 전체 5–8개.

## 2. 질문 공식
| 공식 | 모양 | 가려내는 것 |
|---|---|---|
| 구체 사례 | "{성과}를 낼 때 직접 바꾼 코드나 설정을 하나 골라 설명해 주세요." | 본인 기여, 기술 깊이 |
| 시간순 재구성 | "{장애·사건}이 났던 날을 시간순으로 말해 주세요." | 실제 경험 여부, 대응 순서 |
| 측정 방법 | "{수치}는 어떻게 측정했나요?" | 수치의 근거 |
| 다시 한다면 | "{시스템}을 다시 설계한다면 가장 먼저 바꿀 것은 무엇인가요?" | 한계를 스스로 아는지 |
| 실패 사례 | "{기간} 동안 가장 크게 실패한 {배포·결정}은 무엇이었나요?" | 회고 습관, 책임 범위 |
| 대안 비교 | "{선택}을 고를 때 검토하고 버린 방법은 무엇이었나요?" | 의사결정 근거 |

## 3. 질문마다 넣는 것
- `text`: 질문(해요체, 한 문장)
- `verify`: 확인할 점 — 이 질문으로 무엇을 가려내는지
- `goodSignals`: 좋은 답의 신호 2–3개 (구체적인 도구·지표·순서가 나온다)
- `cautionSignals`: 주의 신호 1–2개 (팀 성과로만 답한다, 수치의 측정 방법을 모른다)
- `fromFlag`: 어느 확인 필요 항목에서 왔는지(있을 때)

## 4. 하지 않는 것
- `fair-hiring.md` 3장의 금지 질문.
- 정답이 하나뿐인 지식 퀴즈. 경험을 묻는다.
- 유도 질문("~하셨죠?"), 압박 질문.
