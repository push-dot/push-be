# Quality Review — 산출물 품질 검증 스킬

선택한 산출물의 언어적, 내용적, 기술적 품질을 종합적으로 검증하는 스킬.

## 실행 조건
- 수정된 산출물 초안이 준비된 경우 (시나리오 A/D)
- 사용자가 이력서만 제공하고 피드백을 요청한 경우 (시나리오 B)
- 최종 출력 전 품질 게이트가 필요한 경우

## 워크플로우
### Step 1: 언어 품질 검사
다음 항목을 검사하고 오류를 P0-P2로 등급 분류:
- 맞춤법 오류
- 문법 오류 (주어-동사 불일치, 시제 불일치)
- 띄어쓰기 오류
- 기술 용어 대소문자 오류 (예: "Github" → "GitHub")
- 중복 표현, 불필요한 워딩

### Step 2: 말투 및 어조 분석
- `_workspace/01_scenario.json`의 `tone` 값을 읽어서 **선택된 말투와 실제 작성된 말투가 일치하는지** 검증
- 전반적인 어조 평가 (전문적인가? 자신감 있는가? 간결한가? 기술적인가? 협업 중심인가?)
- 선택된 말투의 규칙을 위반한 표현 식별 (예: `concise` 말투인데 불필요하게 긴 문장, `confident` 말투인데 수동적인 표현)
- 수동태 과다 사용 여부
- 너무 수동적이거나 공격적인 표현 식별
- 업계/직군에 적합한 어조인지 평가
- 말투 일관성 점수 산정 (1-10): 전체 이력서가 동일한 말투로 유지되는지
- 말투 불일치가 발견되면 P1 등급으로 기록
- plugin `references/writing-voice.md`를 읽고 위반을 P1로 기록한다: 가운데점 `·`, `~인지도`/`~는지` 나열, 경험 본문의 현재형 원칙문, 자기소개서에서 결과 선행 및 `문제는 ~였습니다. 이를 해결하기 위해 ~했습니다` 구조 누락

### Step 3: 내용 일관성 검증
- 날짜/기간의 논리적 일관성 (겹치거나 비지 않는 기간)
- 역할과 경력 수준의 일관성
- 기술 스택과 프로젝트 경험의 일관성 (Java 프로젝트인데 기술 스택에 Java가 없는 경우)
- 이력서 전체에 걸쳐 동일 용어 사용 (예: "Frontend"와 "Front-end" 혼용)

### Step 4: ATS 호환성 검토
1. 공고 키워드와 이력서 키워드 매칭률 계산
2. 중요한 누락 키워드 식별
3. 섹션 헤더가 ATS 친화적인지 확인
4. 복잡한 형식(표, 이미지)이 ATS 파싱을 방해하지 않는지 확인

### Step 4-B: 자기소개서 검증 (선택 시)
`_workspace/03_draft_cover_letter_v{N}.md`가 있으면 다음을 검증한다.

1. `_workspace/02_strategy.json.cover_letter.sections`의 문항, 카테고리, `evidence_refs`, `target_chars`와 초안을 대조한다.
2. 각 섹션에 소제목과 본문이 하나씩 있는지, 섹션 수 N이 전략과 일치하는지 확인한다.
3. 본문이 공고 문항을 답하는지, 공고 요구사항과 실제 경험을 연결하는지 확인한다.
4. 글자 수 제한이 있으면 준수 여부를 확인하고, 없으면 공백 포함 500자 내외인지 확인한다.
5. 같은 경험을 근거 없이 반복하지 않는지, 증명되지 않은 수치·직책·완료 경험이 없는지 확인한다.
6. 지원동기·입사 후 기여는 Phase 2 GATE의 사용자 결정과 일치하는지 확인한다.
7. `references/writing-voice.md`의 자기소개서 문장 구조와 금지 항목을 검사한다.

### Step 5: 종합 평가 리포트 생성
1. `_workspace/04_review_report.json`의 `outputs` 객체에 산출물별로 저장
2. 각 산출물 리포트 항목:
   - `overall_score`: 1-10 점수
   - `issues`: 발견된 문제 (등급별 분류)
   - `strengths`: 강점
   - `suggestions`: 개선 제안
   - `ats_match_rate`: ATS 키워드 매칭률 (%)
   - `summary`: 종합 평가 요약 (3-5문장)
3. P0 이슈가 있으면 산출물별 수정본 저장:
   - `_workspace/04_corrected_resume.md`
   - `_workspace/04_corrected_portfolio.md`
   - `_workspace/04_corrected_cover_letter.md`
4. P0 이슈가 없으면 해당 초안을 유지한다.

## 원칙
- 객관적 기준으로 평가하라 — "좋다/나쁘다"가 아니라 구체적 근거와 함께 평가하라
- P0 이슈(오타, 사실 오류)는 자동 수정하되 변경사항을 투명하게 공개하라
- P1-P2 이슈는 추천으로 제시하고, 사용자에게 수정 여부를 선택하게 하라
- ATS 매칭률은 맹신하지 말고, 키워드의 자연스러운 배치를 더 중요하게 평가하라
- 자기소개서의 글자 수와 문항 충족은 명시 규칙으로 검증하되, 실제 경험 근거보다 키워드를 우선하지 마라

## 검증
- [ ] 모든 오류가 등급(P0/P1/P2)과 함께 기록되었는가?
- [ ] P0 이슈가 자동 수정되었는가?
- [ ] ATS 매칭률이 계산되었는가?
- [ ] 종합 점수와 평가 요약이 포함되었는가?
- [ ] 시나리오 B의 경우, 피드백 리포트가 실행 가능한 조언을 포함하는가?
- [ ] 자기소개서 선택 시 문항·카테고리·근거·글자 수·소제목을 모두 검증했는가?
- [ ] `references/writing-voice.md` 위반이 P1로 기록되었는가?
- [ ] `04_review_report.json.outputs`와 산출물별 수정본이 서로 덮어쓰지 않는가?
