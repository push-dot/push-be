# Job Analyzer — 공고 분석 스킬

채용 공고 자료를 읽고 구조화된 요구사항과 지원 문항 데이터로 변환하는 스킬.

## 실행 조건
- 사용자가 채용 공고 URL, Markdown/PDF, 또는 직접 텍스트를 제공한 경우
- 공고 내용을 기반으로 이력서 맞춤 수정이 필요한 경우
- 어떤 기술과 경험을 강조해야 할지 분석이 필요한 경우

## 워크플로우
### Step 1: 공고 자료 읽기
1. URL은 webfetch로 병렬 fetching하고 실패 시 URL별로 1회 재시도한다.
2. Markdown 파일과 직접 텍스트는 원문을 그대로 읽는다.
3. PDF는 `opendataloader-pdf`를 우선 사용하고, 불가하면 Read 또는 PDF 텍스트 추출 fallback으로 본문을 읽는다.
4. 읽은 원문은 `_workspace/01_job_raw/{index}.md`에 보존하고, URL/파일/텍스트 중 어느 입력인지 source 정보를 함께 기록한다.
5. 읽을 수 없는 자료는 실패 목록에 기록하고 나머지 자료로 계속 진행한다.

### Step 2: 공고 내용 분석
각 공고 자료에 대해 다음 정보 추출:
- **회사 정보**: 회사명, 업종, 문화 (알 수 있으면)
- **기술 스택**: 필수 기술, 우대 기술
- **경험 요구사항**: 최소 경력, 특정 도메인 경험
- **직무 설명**: 주요 책임, 기대 역할
- **우대사항**: 추가 점수가 되는 항목
- **핵심 키워드**: ATS 매칭용 중요 키워드 목록
- **지원 문항**: 자기소개서/지원서에 명시된 질문 원문
- **글자 수 제한**: 문항별 글자 수 또는 분량 제한. 명시되지 않으면 `null`

`application_questions`는 다음 구조로 `_workspace/01_job_analyses.json`에 저장한다:

```json
{
  "prompt": "지원 동기와 입사 후 기여를 작성해 주세요.",
  "character_limit": 500,
  "source_id": "job-01"
}
```

- 문항이나 글자 수를 추정하지 않는다.
- 자기소개서 문항이 없으면 직무 설명, 필수/우대사항, 조직 가치에서 카테고리 후보만 제공한다.

### Step 3: 공고 간 공통점/차이점 분석
1. 여러 공고가 있을 경우 공통 요구사항과 반복되는 지원 문항을 식별한다.
2. 공고별 특화 요구사항과 문항을 구분한다.
3. 공통 자기소개서에는 반복 문항 또는 가장 많은 공고를 포괄하는 요구사항을 우선한다.
4. 공통 문항이 없으면 공통 요구사항만 전달하고, 개별 문항을 하나의 일반 문항으로 합성하지 않는다.

### Step 4: JSON 출력
1. `_workspace/01_job_analyses.json`에 `source`, 요구사항, `application_questions`, 공통점/차이점을 저장
2. 각 공고의 원문도 `_workspace/01_job_raw/{index}.md`에 보존

## 원칙
- 공고 자료의 신뢰성을 판단하지 말고 제공된 내용 그대로 분석하라 — 사용자가 신뢰하는 자료다
- 공고 내용이 부족하면(예: 페이지만 있고 상세 내용 없음) "분석 불가"로 표시하고 추정하지 마라
- 하나의 키워드에 과도하게 가중치를 두지 마라 — 공고의 전체 맥락을 고려하라

## 검증
- [ ] 모든 공고 자료를 읽었는가? (실패 자료 별도 기록)
- [ ] 각 공고의 요구사항이 올바르게 추출되었는가?
- [ ] 공통/특화 요구사항이 구분되었는가?
- [ ] 명시된 지원 문항과 글자 수 제한이 `application_questions`에 보존되었는가?

## 참고
- webfetch 도구 사용. 타임아웃은 URL당 30초
- 병렬 처리: 여러 URL을 한 번에 webfetch 호출
