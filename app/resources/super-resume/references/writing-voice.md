# writing-voice

super-resume 말투·문장구조 규칙. 작성(content-craft)과 검증(quality-review)이 같이 읽는다.

시각 디자인(CSS, 여백, 사진)은 최신 HTML이 담당한다. 이 파일은 문장만 다룬다.

---

## 기본

합니다체. 담백한 1인칭 설명형. 주어를 반복하지 않는다.

한 문장에 검증 가능한 주장 하나. 기술명과 코드 식별자는 영어 원형.

경험은 과거형 `했습니다`. 입사 후 포부만 `하겠습니다`.

동사: 구현했습니다, 구성했습니다, 처리했습니다, 확인했습니다, 나눴습니다, 반영했습니다.

패턴: 문제 → 구현/분리/변경 → 확인한 결과.

## 자기소개서 문장 구조

결과를 먼저 둔다.

```
{결과 또는 한 줄 주제}
{기간/프로젝트}에 참여했습니다.
문제는 {문제}였습니다. 이를 해결하기 위해 {조치}했습니다.
{확인한 결과}했습니다.
```

지원동기: {한 일}했습니다. {회사의 일}에 활용하고 싶어 지원했습니다.
입사 후: 고객에게 불편이 생기는 지점부터 이해한 다음, 범위를 정해 구현하겠습니다.

소제목은 명사구. 완료 문장이나 현재형 선언을 소제목으로 쓰지 않는다.

## 금지

| 쓰지 말 것 | 대신 |
|---|---|
| 가운데점 `·` | 쉼표 또는 문장 분리 |
| `~인지도`, `~는지` 나열 | `{대상}을 확인했습니다` |
| 현재형 원칙문 (`합니다`, `봅니다`, `받습니다`, `확인합니다`) | `했습니다`, `반영했습니다` |
| 중간점 나열 (`중지와 탭 전환`, `다시 찾기·질문 수정`) | 문장으로 풀기 |
| 구어 (`쓰고`, `돌아간다`, `막히는지`, `돼도`) | `사용하고`, `동작한다`, `불편이 생기는 지점`, `되어도` |
| 리뷰어 말 (`받다`, `통과 기준`, `컴포넌트 책임`) | `반영했습니다`, `확인 기준`, `컴포넌트 역할` |
| 회사 제품 지적 | 내가 구현한 방식만 |
| 과장, 추정, 확인하지 않은 수치 | 근거 있는 사실만 |
| AI 도구 이름 나열 | 검증 범위와 결과만 (사용자가 도구명을 원할 때만) |

`관심을 두고 있습니다`처럼 원본 인사/관심 문장은 유지할 수 있다. 경험 본문은 `했습니다`.

## 산출물별

이력서 불릿: `{문제}여서 {조치}했습니다. {남은 상태}만 남았습니다.`

포트폴리오 사례: 문제 문단 → 조치 문단 → 검증 문단. 표 없이 근거 링크.

자기소개서: 소제목 + 본문. 사진 없음. 지원 조건(`산업기능요원 보충역`)은 헤더에 유지.

## 적용 순서

1. `_workspace/01_tone_profile.json`의 원본 말투를 읽는다.
2. 이 파일의 금지와 자기소개서 구조를 덮어쓴다. 원본 말투보다 이 파일이 우선한다.
3. `_workspace/03_tone_applied.json`에 적용 결과를 기록한다.

## 검증

- [ ] `·` 없음
- [ ] `인지도` / `는지` 나열 없음
- [ ] 경험 본문이 `했습니다`이고 원칙문 현재형이 없음
- [ ] 자기소개서가 결과 먼저, `문제는 ~였습니다. 이를 해결하기 위해 ~했습니다`
- [ ] 한 문장 한 주장
- [ ] 확인되지 않은 수치가 없음
- [ ] 지원 조건 누락 없음
